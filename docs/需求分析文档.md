## 1. 项目概述

### 1.1 项目背景

本项目是一套面向**个人站长**的全栈博客系统，主题风格为「晴天」（天空蓝 / 薄荷青 / 暖阳金）。系统在传统博客的「文章 + 分类 + 标签 + 评论」核心之上，扩展了项目集、在线工具箱、留言板、友链、邮箱订阅、访问统计、天气卡等模块，形成一个**个人技术门户**而非单纯的文章列表站。

### 1.2 项目定位

- **单站长模型**：系统内只有一个 `ADMIN` 角色账号，无多作者/多租户需求。
- **访客免注册**：所有前台互动（评论、留言、点赞、举报、友链申请、邮箱订阅）均为匿名或邮箱标识，不建立访客账号体系。
- **自主可控**：图床本地化（不依赖第三方对象存储）、IP 地理解析离线化（ip2region）、天气数据取自免费公开 API（Open-Meteo），最小化外部依赖与费用。

### 1.3 系统规模（当前实现）

| 维度 | 数量 |
|---|---|
| 后端 Java 类 | 147 个 |
| 后端 REST 控制器 | 32 个 |

| 前端 Vue 组件/页面 | 77 个 |
| 前台页面路由 | 13 条 |
| 后台页面路由 | 13 条 |

## 2. 目标与范围

### 2.1 业务目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 提供完整的内容创作与发布闭环 | 站长可在后台完成写作、配图、分类打标、发布、归档全流程 |
| G2 | 提供多形态内容展示（文章 / 项目 / 工具） | 三类内容各有独立前台页面与后台管理 |
| G3 | 建立访客与站长的双向互动通道 | 评论、留言、友链申请、邮箱订阅四条通道均可用且有邮件通知 |
| G4 | 提供可运营的数据支撑 | 后台可查看 PV/UV、设备与地域分布、内容热度排行 |
| G5 | 保证站点在公网长期稳定自托管运行 | 一键发布脚本 + systemd + Nginx + HTTPS 自动续期 |
| G6 | 保护站长与访客隐私 | 配置脱敏、评论隐私字段剥离、访客 IP 不对外暴露 |

### 2.2 范围内（In Scope）

- 文章全生命周期管理（草稿 / 发布 / 归档、置顶、推荐、密码保护、阅读量校正）
- 文章导入导出（Markdown / DOCX / PDF，单篇与整库 zip）
- 分类、标签、项目、项目分类、工具、工具分类的 CRUD 与排序
- 评论与留言板（审核、精选、点赞、举报、站长回复）
- 友情链接（访客申请 + 后台审核 + 推荐标记）
- 邮箱订阅与内容自动通知（双确认 + 定时推送）
- 站点配置中心（白名单 key-value）
- 访问统计与操作日志
- 分享点击统计（六渠道）
- 首页实时天气卡
- 站长个人中心（资料、改密）
- 部署脚本与数据库迁移规范

### 2.3 范围外（Out of Scope）

- 多用户注册 / 多作者协作 / 权限分级（仅单 ADMIN）
- 付费内容 / 会员体系 / 电商
- 全文检索引擎（当前为数据库 LIKE 搜索）
- 移动端原生 App
- 第三方对象存储（七牛云 SDK 已引入但默认不启用）
- RSS 订阅（已由邮箱订阅替代）
- 独立页面 CMS（原 Page 模块已下线，并入项目分类体系）

## 3. 角色与用户画像

### 3.1 角色定义

| 角色 | 标识 | 认证方式 | 权限范围 |
|---|---|---|---|
| 站长（管理员） | `ROLE_ADMIN` | 用户名密码登录换取 JWT | `/api/v1/admin/**` 全部接口 + 全部前台接口 |
| 匿名访客 | 无 | 无认证，按 IP + UA 识别 | 公开只读接口 + 受限写入接口（评论/留言/点赞/举报/友链申请/订阅/分享上报/头像上传） |
| 订阅者 | 邮箱 + token | 邮件链接中的一次性 token | 确认订阅、退订两个 GET 接口 |
| 系统调度 | 无 | 内部 `@Scheduled` | 内容通知推送、限流器清理 |

### 3.2 典型用户旅程

**站长发文旅程**
登录后台 → 新建文章（Tiptap 富文本 / MdEditor）→ 上传封面与插图到本地图床 → 选择分类、打标签、填写 slug 与摘要 → 保存草稿或直接发布 → 定时任务在 5 分钟内向已确认订阅者推送新文通知 → 后台查看阅读量与评论。

**访客阅读旅程**
进入首页（看到天气卡 + 站点统计 + 推荐文章 + 最新文章）→ 点击文章 → 阅读正文（代码高亮、目录、相关文章）→ 分享到微信/微博/QQ/豆瓣或复制链接 → 在文末发表评论（可能需算术验证码）→ 评论进入待审核 → 站长审核通过后邮件通知评论者。

**订阅者旅程**
在页面提交邮箱 → 收到确认邮件 → 点击确认链接（状态 pending → confirmed）→ 此后每有新文章/项目/工具发布即收到邮件 → 任意邮件底部点退订链接（状态 → unsubscribed）。

| 评论被回复 | 被回复者 | 站长或他人回复后 |

规则：邮件异步发送（`@Async("mailTaskExecutor")`），发送失败兜底不抛异常、不影响主流程；同一收件人 1 小时内最多 1 封通知邮件（按邮箱哈希频控）。

## 5. 非功能需求

### 5.1 安全需求

| 编号 | 需求 | 实现要点 |
|---|---|---|
| NFR-S-01 | 无状态认证 | Spring Security `STATELESS` + JWT Bearer；CSRF 关闭（无 Cookie 会话） |
| NFR-S-02 | 密钥强度 | `BLOG_JWT_SECRET` 必填，缺失时应用启动失败；建议 ≥64 字节随机 |
| NFR-S-03 | 密码存储 | BCrypt cost=12（约 250ms/次，抗离线爆破） |
| NFR-S-04 | Token 撤销 | JWT 黑名单，登出与改密即时失效 |
| NFR-S-05 | 接口鉴权分层 | 公开白名单精确列举；`/api/v1/admin/**` 强制 `hasRole('ADMIN')`；其余 `authenticated()` |
| NFR-S-06 | Swagger 生产关闭 | 仅 dev profile 放行 `/swagger-ui/**` 与 `/v3/api-docs/**` |
| NFR-S-07 | CORS 白名单 | 显式 origin 列举，不使用 pattern，避免 `Origin: null` / `file://` 绕过 |
| NFR-S-08 | 全接口频控 | 登录、评论、举报、上传、友链申请、订阅、分享、导入八类接口均有 IP/邮箱维度限流 |
| NFR-S-09 | 配置 key 白名单 | 站点配置保存必须**精确匹配**白名单，禁止 `startsWith` 前缀绕过 |
| NFR-S-10 | CSV 注入防护 | 订阅者导出对 `=`/`+`/`-`/`@` 开头字段做转义 |
| NFR-S-11 | 敏感配置不入库 | `application.yml` / `application-prod.yml` 由 `.gitignore` 屏蔽，仅保留 `application-example.yml` 模板 |
| NFR-S-12 | 端口收敛 | 3306 / 6379 / 8080 仅监听 `127.0.0.1`，统一经 Nginx 443 反代 |

| 实体 | 字段 | 状态定义 |
|---|---|---|

| 举报 | `status` | 0=待处理 1=已处理 2=已驳回 |
| 友链 | `status` | 0=待审核 1=已通过 2=已拒绝 |
| 项目 | `status` | 0=下架 1=已发布 |
| 工具 | `status` | 0=下线 1=正常 2=维护中 3=预告 |

### 6.3 数据迁移规范（强约束）

1. **新库**走 `blog-server/src/main/resources/db/init.sql`（建表 + 种子数据）。
2. **增量**走 `server-config/migration-*.sql`，统一使用 `information_schema` 探测 + `ALTER ADD COLUMN` / `CREATE TABLE IF NOT EXISTS` / `ON DUPLICATE KEY UPDATE`，保证幂等可重复执行。
3. **每次加表/加列必须 init.sql 与迁移脚本双写**，否则新库缺列。
4. `CREATE TABLE IF NOT EXISTS` 在表已存在时整段跳过、**不补列**；老库补列必须写动态 `PREPARE/EXECUTE ALTER`（no-op 分支用 `DO 0`）。
5. 改 Java 实体前必须先把迁移 SQL 跑进目标库，否则 MyBatis-Plus 报 `Unknown column` / `Data too long` 导致接口 500。

## 10. 约束与假设

### 10.1 约束

| 编号 | 约束 |
|---|---|
| C-01 | 单管理员模型，无多作者协作能力 |
| C-02 | 留言板复用 comment 表并绑定 `article_id=1`，该 ID 为系统保留，不可作为普通文章使用 |
| C-03 | 搜索基于数据库模糊匹配，数据量增大后性能与相关性受限 |
| C-04 | Caffeine 为单机本地缓存，多实例部署会出现缓存不一致（当前为单实例部署） |
| C-05 | JWT 黑名单存于应用内存/Redis，应用重启后黑名单可能丢失 |
| C-06 | docx / pdf 导入导出依赖服务器安装 pandoc，缺失时该通道不可用 |
| C-07 | ip2region 数据文件约 11MB，需单独下载（部分 CDN raw 直链对大文件返回错误页；仓库版本走 Git LFS，`git clone` 默认拉不到真实数据） |
| C-08 | 天气数据依赖公网第三方免费 API，无 SLA 保障 |
| C-09 | 前端为 SPA，SEO 依赖服务端配置与站点配置中的 SEO 字段，无 SSR |

### 10.2 假设

- 站点为个人低并发场景（日 PV 千级以内），单机部署足够
- 站长具备基础 Linux 运维能力，能完成 systemd / Nginx / certbot 配置
- 访客量级下 BCrypt cost=12 的登录耗时（~250ms）可接受
- 邮件量级不触发 SMTP 服务商的发送频率限制

## 11. 演进方向（建议）

| 优先级 | 事项 | 理由 |
|---|---|---|
| 高 | 引入自动化测试（当前仅有 test starter 依赖，无实质测试用例） | 19 张表、32 个控制器的回归成本已很高 |
| 高 | 搜索能力升级（MySQL 全文索引或轻量检索引擎） | 当前 LIKE 匹配在文章量增长后相关性与性能均不足 |
| 中 | 缓存统一到 Redis | 为将来多实例部署与 JWT 黑名单持久化铺路 |
| 中 | SEO 增强（预渲染或 SSR） | SPA 对搜索引擎收录不友好 |
| 中 | 访问统计增加时间范围对比与趋势图 | 当前以「今日」为主，缺少周/月趋势 |
| 低 | 工具箱开放插件式接入 | 当前工具为配置化跳转，扩展需改前端路由 |
| 低 | 评论第三方登录（GitHub OAuth） | 降低垃圾评论比例，替代算术验证码 |

## 附录 A：术语表

| 术语 | 含义 |
|---|---|
| slug | URL 友好的唯一短标识，用于文章/分类/标签/项目分类/工具的路由 |
| 双确认（Double Opt-in） | 邮箱订阅需经「提交 → 收邮件 → 点链接确认」两步方生效 |
| notified 标记 | 文章/项目/工具上的推送幂等位，防止同一内容重复推送订阅者 |
| 会话级去重 | 访问日志按「IP + UA」在时间窗口内只记一次 |
| WMO Code | 世界气象组织天气现象代码，Open-Meteo 返回值 |
| 幂等迁移 | 可重复执行且结果一致的 SQL 迁移脚本 |
| 逻辑删除 | 通过 `deleted` 字段标记删除，数据不物理移除（`@TableLogic`） |
