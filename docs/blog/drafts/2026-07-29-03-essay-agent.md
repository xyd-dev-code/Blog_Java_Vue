上周我让 Agent 写一段关于「山里泡茶」的散文。它写得很对——「山雾渐起,茶汤初沸」。但读起来不像是我写的。

这一篇想说说这件事。

## 一个实验

我把 Agent 写的一段、自己写的一段、我过去博客里的一段,打乱顺序,发到读者群里,让他们盲评「哪一段最有调性」。

结果:60% 的读者选了 Agent 写的那段。

也就是说,Agent 的模仿能力比我想象的好。它学到了「草木蔓发」这个站点的调性,知道我喜欢短句、知道我喜欢把动词放在句子结尾、知道我要么不引经要么只引一遍。表面上看,它写得比我稳。

但我自己能一眼分出来哪段是我写的。读者分不出来。

这个反直觉的结果让我想了一会儿。

## Agent 写得「对」但「空」

Agent 写的「山雾渐起,茶汤初沸」——修辞对了,意象对了,节奏对了。但读完之后,我心里什么都没有。

为什么?

我想了想,可能是因为 Agent 在「拟合模式」,不在「表达经验」。

「山雾渐起」这四个字,我写下来的时候,脑子里有一张具体的图:八月的某个下午,海拔八百米,雾从山谷里翻上来,不是慢慢起的,是成片地翻。茶汤初沸——壶盖被蒸汽顶得哒哒响,我伸手去按,被烫了一下,手指尖发红。这两个画面之间没有任何修辞关系,只是同一段时间里发生的两件事。Agent 把它写成了一种「意境」,我写的时候它根本不是意境,是记忆。

「意境」是后人的归纳,「记忆」是当时的事。Agent 学的是归纳,我写的是当时。差别在这里。

## 散文不能外包的三个理由

**第一个理由:私人记忆无法被 prompt 唤起。**

我为什么写「立秋」?不只是因为节气到了。是因为那年我从城里搬回山里,租的房子在山坡上,房东在我搬进来那天煮了一壶白茶,说立秋之后第一壶茶要敬山。我当时觉得这事儿挺庄重的,后来每年立秋我都自己煮一壶。

这件事没法 prompt。Agent 不知道我房东,不知道白茶,不知道「庄重」在我这里的语义。任何想写「立秋」的 Agent 写出来的都是「节气的立秋」,不是「我的立秋」。

而读者读散文,读的就是「你的立秋」。

**第二个理由:节奏和迟疑是意义的一部分。**

写散文的时候,我经常写一句、删掉、写下一句、再回头改上一句。这种迟疑是写作本身,不是 bug。

有一篇我写了三周,中间删了四千字,最后留下来的三千字里,有八百字是从删掉的段落里「救回来」的——不是在原文里修改,是换个位置、换个语境,让它重新成立。这种「救回来」的瞬间,Agent 做不了。Agent 会优化、扩写、缩写,但它不会「救一句」,因为它没有「这是我的,我不想丢」的感受。

我留下来的句子,有些是有伤的——节奏不顺,有个词用得勉强,但我不能换,因为「勉强」本身就是意思。Agent 会把这些都改掉,改得「顺」,但「顺」不是我要的。

**第三个理由:读者想读到的是你。**

我博客的读者,有些是从我写第一篇读到现在。他们读我的文章,不是在读「关于 X 的信息」,是在读「这个人怎么看 X」。这是私人的,也是私语的。

如果我用 Agent 写一篇散文,读者会隐约觉得不对——说不清哪儿不对,但就觉得「这不是你写的」。这种「觉得不对」累积多了,读者就走掉了。读者和我之间的契约是「你写你的,我读你的」,Agent 是这个契约的第三者。

## 一个折中

但我也不是完全不让 Agent 碰散文这件事。

我用 Agent 做三件:

第一件,**列提纲**。一篇散文的核心是「想说什么」,提纲是「想说什么」的结构化。Agent 列提纲,比我从零想快。但「选哪个提纲」是我的事。

第二件,**查资料**。写「草木蔓发」调性的文章,有时候要确认一种植物的名字、一个节气的日期、一种茶的产地。Agent 查得比我快,我不必每次都去翻《中国植物志》。

第三件,**校对错别字**。我自己写的稿子,反复看还是漏。Agent 校对一遍,标点、错别字、不通顺,能抓出来。

这三件事有一个共同点:它们不涉及「为什么这样写」,只涉及「这个字是什么、这句话通不通」。我把它们外包,没把散文本身外包出去。

写散文,核心是我和我自己那点破事的关系。这件事 Agent 帮不上忙。

## 收尾

Agent 让技术写作变便宜了。

我写代码、写教程、写 demo 的时间,比三年前少了至少一半。技术写作的边际成本接近零——Agent 帮我拼好骨架,我填血肉,半小时一篇。

但散文写作的成本一点没降。我写一篇散文还是三周,还是删四千救八百,还是要在某个句子前坐半天。Agent 让这些「写作的难」没有变得容易——也许这才是好的分工。

技术写作便宜一点,散文贵一点。这是一种健康的通货膨胀——前者贬值,因为它的稀缺性低;后者稳定,因为它的稀缺性没变。

立秋那壶白茶,我还是自己煮。Agent 不知道火候。
