Agent 看起来很玄,但拆到最底层,就是「模型说一句,我跑一句,跑完把结果喂回去」这个循环 30 次。

不玄。但 30 次循环里有不少细节。这篇带你看清楚每一步,然后我们写一个能跑本地命令的玩具 Agent——不超过 200 行 Node.js。

## 三个常见误解

**误解一:Agent 就是更聪明的 ChatGPT。** 错。ChatGPT 是「一问一答」,Agent 是「一问多步」。区别在于 Agent 能调用工具,工具能返回真实结果(读文件、跑命令、查数据库),模型根据真实结果决定下一步。

**误解二:Agent 能自己决定做什么。** 错。工具集和边界必须由人定。你给 Agent 暴露 `rm -rf`,它就敢删;你不暴露,它就删不了。「Agent 自主」是有限度的,限度由代码框定。

**误解三:Agent 越复杂越好。** 错。最小骨架够用。复杂的 Agent 框架(LangChain、AutoGen)解决的问题是「工具管理」和「上下文压缩」,但你第一个玩具不需要这些。先跑通,再考虑优化。

## 最小骨架

Agent 的核心数据结构是一个消息数组。每条消息有 role(用户/助手/工具),有 content,有可选的 tool_calls。循环就是反复发请求、收 tool_calls、执行工具、把结果塞回数组。

Node.js 实现:

```javascript
import Anthropic from '@anthropic-ai/sdk'

const client = new Anthropic()

// 工具定义:模型看到的 schema
const tools = [
  {
    name: 'exec',
    description: '运行一条 shell 命令,返回 stdout/stderr',
    input_schema: {
      type: 'object',
      properties: {
        cmd: { type: 'string', description: '要执行的命令' }
      },
      required: ['cmd']
    }
  }
]

// 工具执行器:模型看不到的代码
async function exec({ cmd }) {
  const { spawn } = await import('node:child_process')
  return new Promise((resolve) => {
    const p = spawn('sh', ['-c', cmd])
    let out = '', err = ''
    p.stdout.on('data', d => out += d)
    p.stderr.on('data', d => err += d)
    p.on('close', code => resolve({ stdout: out, stderr: err, code }))
  })
}

// Agent 循环
async function run(userMessage) {
  const messages = [{ role: 'user', content: userMessage }]

  while (true) {
    const resp = await client.messages.create({
      model: 'claude-sonnet-4-6',
      max_tokens: 1024,
      tools,
      messages
    })

    // 把助手的回复塞回消息数组
    messages.push({ role: 'assistant', content: resp.content })

    // 退出条件:模型不再调用工具
    if (resp.stop_reason !== 'tool_use') {
      return resp.content.find(b => b.type === 'text')?.text
    }

    // 执行所有 tool calls,把结果塞回去
    for (const block of resp.content.filter(b => b.type === 'tool_use')) {
      const result = await exec(block.input)
      messages.push({
        role: 'user',
        content: [{
          type: 'tool_result',
          tool_use_id: block.id,
          content: JSON.stringify(result)
        }]
      })
    }
  }
}

run('列出当前目录下最近修改的 5 个 .vue 文件').then(console.log)
```

跑一下,大概十秒后你会看到:

```
我用 exec 工具执行 `find . -name '*.vue' -mtime -30 | head -5`,得到:
1. src/views/Home.vue
2. src/views/admin/ArticleList.vue
...
```

这就是 Agent 的全部秘密。

## 把它接到 Claude API 上

上面那段代码已经接好了。但生产环境要补几行错误处理:

```javascript
// 限流重试
async function withRetry(fn, attempts = 3) {
  for (let i = 0; i < attempts; i++) {
    try { return await fn() }
    catch (e) {
      if (e.status === 429 && i < attempts - 1) {
        await new Promise(r => setTimeout(r, 1000 * (i + 1)))
        continue
      }
      throw e
    }
  }
}

// 调用处换一下
const resp = await withRetry(() => client.messages.create({ ... }))
```

```javascript
// tool_call 解析失败:模型有时候会返回格式错误的 input
for (const block of resp.content.filter(b => b.type === 'tool_use')) {
  if (!block.input || typeof block.input !== 'object') {
    messages.push({
      role: 'user',
      content: [{
        type: 'tool_result',
        tool_use_id: block.id,
        content: JSON.stringify({ error: 'invalid input' }),
        is_error: true
      }]
    })
    continue
  }
  // ... 正常执行
}
```

// 工具超时兜底:不让一个 hang 住的命令拖垮整个循环
async function exec({ cmd }) {

  return Promise.race([

## 安全围栏

这是我最想强调的部分。

玩具可以随便玩。但 Agent 一旦能跑本地命令,它就有了「破坏力」。你不会给一个陌生人 `rm -rf` 权限,也不应该给 Agent。

**第一道:工具白名单。** 我玩具里的 `exec` 工具就是「任意命令」,这是为了演示清楚。生产里应该改成:

```javascript
const tools = [
  {
    name: 'list_vue_files',
    description: '列出最近修改的 .vue 文件',
    input_schema: { type: 'object', properties: {} }
  },
  {
    name: 'read_file',
    description: '读取一个文件的内容',
    input_schema: {
      type: 'object',
      properties: { path: { type: 'string' } },
      required: ['path']
    }
  }
]

// 执行器只暴露有限的命令
async function list_vue_files() {
  return exec({ cmd: "find . -name '*.vue' -mtime -30 | head -10" })
}

async function read_file({ path }) {
  // 路径白名单:只在工作目录里读
  if (!path.startsWith(SAFE_ROOT)) {
    return { error: 'path outside safe root' }
  }
  return exec({ cmd: `cat ${path}` })
}
```

**第二道:危险操作走二次确认。** 任何「写」操作(修改文件、提交 git、删除)不应该直接执行。应该是:

1. Agent 报告「我打算做 X,理由是 Y」
2. 人看一眼,同意或否决
3. 同意才执行

实现上,把这类工具做成「dry-run」:

```javascript
async function propose_git_commit({ message }) {
  return {
    proposed: true,
    action: `git commit -m "${message}"`,
    // 不执行,只报告
  }
}
```

人看到 proposed 输出,自己跑到终端执行。

**第三道:沙箱。** 工作目录限制。Docker / chroot / macOS sandbox-exec 都可以。玩具阶段不用,但生产前必须有。

## 我用这个玩具做什么

写完这篇的初稿,我用它做了几件事:

- 列出我博客代码里所有用了 `var` 的地方(我自己 replace 不放心,Agent 列出来我逐个确认)
- 找某个被引用但找不到定义的函数(grep + cat 三步)
- 把 markdown 草稿里的相对路径批量校验

每件事花一分钟到五分钟。没有这个玩具,我大概会花三十分钟到一小时。

Agent 不是让我「变强」,是让我「跳过不重要的环节」。跳过的环节越多,我能花在不跳过的地方的时间越多。
